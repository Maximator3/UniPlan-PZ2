# UniPlan — Frontend System Design (ПЗ №3)

## Архітектура

UniPlan — клієнтський React-застосунок для навчального планування. Шість екранів: Огляд, Завдання, Календар, Розклад, Предмети, Налаштування.

- `src/components/index.js` — перевикористовуваний UI-kit: `Button`, `Input`, `Select`, `Badge`, `Card`, `NavItem`, `StatCard`, `TaskCard`, `EmptyState`, `Icon`, `Modal`.
- `src/stories/` — Storybook-історії компонентів, їхніх станів і токенів.
- `src/App.js` — екранні представлення, форми, навігація, сценарії.
- `src/styles.css` — дизайн-токени, компоненти, адаптивність, стани клавіатурного фокусу.

Компоненти не дублюються на екранах: кнопки мають варіанти через `variant`, `size`, `disabled`; бейджі — `tone`; поля — `error`/`required`; `Modal` спільний для форм предмета, заняття, завдання й перегляду деталей. `TaskCard` повторно використовується в Огляді та Завданнях.

## Керування станом

Дані предметів, завдань, занять і семестру знаходяться у `App.state.data`. Метод `updateData` оновлює копію стану та зберігає її в `localStorage` під ключем `uniplan_v2_data`. Стан UI — вибраний екран, модальні вікна, фільтри, пошук, календарна дата — керується в `App`; введені значення та помилки — локальним станом класових компонентів форм.

Для невеликого соло-MVP немає потреби в Redux або серверному кешуванні. Дані не синхронізуються між пристроями, залежать від поточного браузера й можуть зникнути після очищення `localStorage`. Для майбутньої масштабованої версії знадобляться API, авторизація та база даних.

## Стек і деплой

React 18 + Vite 6 (custom code), Storybook 8 для UI-kit, GitHub для контролю версій, Vercel для статичного хостингу. Репозиторій: https://github.com/Maximator3/UniPlan-PZ2 . Сайт: https://uniplan-two.vercel.app/ . Vercel автоматично збирає `npm run build` із гілки `main` та публікує каталог `dist`.

Переваги: безсерверний та економний для навчального MVP, швидка збірка, контроль коду, прості зміни компонентів. Обмеження: локальні дані, відсутність синхронізації. Оптимізації для великих обсягів (віртуалізація списків, code splitting) наразі не потрібні; у майбутньому їх можна додати.

## Доступність (оновлення ПЗ №3)

Додано семантичні `header/nav/main/button`, видимий фокус, skip-link, контрастніші кольори, `aria-current` навігації, `aria-pressed` у календарі, доступні описи прогресу й помилок. У модальних вікнах передбачено Escape, Tab/Shift+Tab, початковий фокус і повернення фокусу після закриття. Мобільна навігація прихована від фокусування, коли закрита.

Це опис реалізованих змін **у гілці перевірки**, а не твердження про проходження повного аудиту WCAG. Після злиття треба повторно перевірити клавіатурний flow, мобільну версію й Lighthouse/axe на публічному сайті.
