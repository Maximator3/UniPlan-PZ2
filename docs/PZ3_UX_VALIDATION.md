# ПЗ №3 — UX-валідація та тестовий план

## Метод

Експертна евристична оцінка інтерфейсу UniPlan за 10 евристиками Нільсена. Цей метод дозволено умовою завдання як альтернативу тестуванню 3–5 користувачів. **Це не інтерв'ю й не реальне користувацьке тестування.** Аналіз зроблено за поточним кодом та екранами; нижче зафіксовано проблеми й корекції.

| Евристика | Спостереження | Виправлення / рішення |
|---|---|---|
| 1. Видимість стану системи | Стани завдань, сповіщення та прогрес присутні, але підписи були світлі | Покращено контраст підписів та статусів |
| 2. Відповідність реальному світу | Продукт використовує поняття предмета, пари й дедлайну | Студентські терміни збережено |
| 3. Контроль і свобода користувача | Діалоги не закривалися Escape | Додано Escape, фокус повертається після закриття |
| 4. Послідовність і стандарти | Бренд-кнопка була `div` з обробником кліку | Замінено на справжню кнопку; збережено повторне використання UI-kit |
| 5. Запобігання помилкам | Є перевірка форм, але зв'язок тексту помилки з полем був недостатнім | Додано `aria-invalid`, `aria-describedby`, `role=alert` |
| 6. Впізнавання замість пригадування | Активний розділ і дата позначалися переважно кольором | Додано `aria-current` і `aria-pressed` |
| 7. Гнучкість і ефективність | При відкритій формі Tab міг переводити фокус за модальне вікно | Додано обмеження фокусу в діалозі та skip-link |
| 8. Естетика й мінімалізм | Композиція проста, але дрібний текст був недостатньо контрастним | Оновлено текстові кольори без зміни структури |
| 9. Допомога в розпізнаванні помилок | Помилки форм були візуально помітними не всім | Пов'язано текст помилки з полем, посилено контраст |
| 10. Довідка і документація | Пояснення локального збереження є в Налаштуваннях | Додано документ архітектури й план тестів |

**Пріоритети:** P1 — клавіатурні діалоги й контраст; P2 — семантика, мобільний фокус, оголошення статусів. Зміни перебувають у PR до перевірки. Не заявляйте про завершене приймальне тестування без фактичних результатів.

## План перевірки після merge і деплою

| Перевірка | Дія | Очікуваний результат |
|---|---|---|
| Production build | `npm ci && npm run build` | Завершення без помилок |
| Storybook build | `npm run build-storybook` | Збірка без помилок |
| Екрани | Перейти в 6 розділів | Усі відкриваються |
| Створення предмета | Додати предмет | З'являється у списку та формі завдання |
| Створення завдання | Вказати предмет, дату, пріоритет | З'являється у списку й календарі |
| Підзадачі | Створити й завершити два кроки | Прогрес змінюється |
| Persist | Перезавантажити сторінку | Дані залишаються в цьому браузері |
| Модальні форми | Відкрити, натискати Tab / Shift+Tab, Escape | Фокус не виходить за діалог, Escape закриває, фокус повертається |
| Клавіатура | Пройти головний flow без миші | Видимий фокус, доступні всі ключові кнопки |
| Mobile | DevTools: 360×800 та 390×844 | Немає горизонтального скролу, меню і форми зручні |
| A11y | Lighthouse/axe на опублікованому сайті | Перевірити WCAG AA, особливо 4,5:1 для звичайного тексту |

Зберігайте реальні скріншоти тестів із датами для PDF та захисту. Порівнювати проблему «до» й виправлення «після» без підтвердження тестування не слід.
